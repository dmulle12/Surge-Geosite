A Cloudflare Workers-based service that converts Loyalsoldier's geosite/geoip datasets into Surge-compatible plain-text rulesets on demand, while also serving JSON indexes and SRS bundle files. It ships with a frontend browser (Cloudflare Pages) for quick browsing, previewing, and searching.

👉 Deployment guide (including CI and Cloudflare setup): [docs/deploy.md](docs/deploy.md)

## Features

- Dynamically generates Surge rulesets (from geosite.dat / geoip.dat)
- Serves JSON indexes and `.srs` bundle files for easy Surge import
- Caching with R2 and Workers KV to reduce cold starts and bandwidth
- Automation scripts and workflows to keep data up to date
- Frontend supports ruleset browsing, filtering, and search

## Usage (hosted service)

Examples below use the public deployment `https://api-surge-geosite.dmuller.tech` (you can also deploy your own domain):

### GeoSite rulesets

- Endpoint: `GET https://api-surge-geosite.dmuller.tech/geosite/<name>[@filter]`
- Filters: `@cn`, `@!cn`, or region tags from the upstream data
- Example: `https://api-surge-geosite.dmuller.tech/geosite/apple@cn`
- SRS: `https://api-surge-geosite.dmuller.tech/srs-geosite/<name>.srs`

### GeoIP rulesets

- Endpoint: `GET https://api-surge-geosite.dmuller.tech/geoip/<name>[@v4|@v6]`
- Example: `https://api-surge-geosite.dmuller.tech/geoip/cn@v4`
- SRS: `https://api-surge-geosite.dmuller.tech/srs-geoip/<name>.srs`

### Index endpoints

- Geosite JSON: `https://api-surge-geosite.dmuller.tech/geosite`
- GeoIP JSON: `https://api-surge-geosite.dmuller.tech/geoip`

### Egern rulesets

- GeoSite (YAML): `GET https://api-surge-geosite.dmuller.tech/egern/geosite/<name>[@filter]`
  - Filters: same as Surge, supports `@cn`, `@!cn` and other attribute filters
  - Output includes: `domain_set` (exact domains), `domain_suffix_set` (suffix matches), `domain_keyword_set` (keywords, derived from simple alternation regexes), `domain_regex_set` (complex regexes)
  - Example: `https://api-surge-geosite.dmuller.tech/egern/geosite/apple@cn`
- GeoIP (YAML): `GET https://api-surge-geosite.dmuller.tech/egern/geoip/<name>[@v4|@v6]`
  - Output includes: `ip_cidr_set` (IPv4), `ip_cidr6_set` (IPv6)
 - Example: `https://api-surge-geosite.dmuller.tech/egern/geoip/cn@v4`

Example (partial):

```yaml
domain_set:
  - www.apple.com
domain_suffix_set:
  - apple.com
domain_keyword_set:
  - google
  - youtube
domain_regex_set:
  - "google|gstatic|youtube"
ip_cidr_set:
  - "192.168.0.0/16"
ip_cidr6_set:
 - "2400:cb00::/32"
```

Note: upstream geosite has no "keyword" type; `domain_keyword_set` is only auto-generated from simple alternation regexes (e.g. `google|youtube`, optionally wrapped in `^...$`/`(?:...)` with no other regex metacharacters), otherwise they stay in `domain_regex_set`.
Also: empty sets are omitted (e.g. no `ip_cidr6_set` key when there are no IPv6 entries).

### Mihomo MRS rulesets

- GeoSite (MRS): `GET https://api-surge-geosite.dmuller.tech/mihomo/geosite/<name>[@filter].mrs`
  - Filters: same as SRS, supports `@cn`, `@!cn` and other attribute filters
  - Example: `https://api-surge-geosite.dmuller.tech/mihomo/geosite/apple@cn.mrs`
- GeoIP (MRS): `GET https://api-surge-geosite.dmuller.tech/mihomo/geoip/<name>[@v4|@v6].mrs`
  - Example: `https://api-surge-geosite.dmuller.tech/mihomo/geoip/cn@v4.mrs`

Note: MRS is the binary ruleset format for mihomo/Clash.Meta. GeoSite MRS excludes regex rules (mihomo domain behavior limitation).

## Local development

1) Install dependencies and tools

- Node.js 20.18+ (22 LTS recommended), npm, Wrangler 4.x

2) Start the local service

```bash
npm install
npm run dev   # http://localhost:8787
```

3) Verify endpoints

- Visit `GET /geosite/apple@cn` and similar URLs to verify rule rendering

Frontend development (optional, `frontend/` directory):

```bash
cd frontend
npm install
npm run dev   # http://localhost:3000
```

## Deployment (summary)

- Worker: `npm run deploy` (publishes to Cloudflare Workers; configure bindings in `wrangler.toml` first and set secrets via `wrangler secret put`)
- Pages (frontend): see the Pages section in [docs/deploy.md](docs/deploy.md); point to your Worker API via environment variables or `_redirects`
- GitHub Actions: see the Worker/Pages CI examples in [docs/deploy.md](docs/deploy.md)

## Data regeneration & tooling

- Regenerate geosite artifacts: `npm run build:geosite`
- Regenerate geoip artifacts: `npm run build:geoip`
- Build SRS: `npm run build:srs`, `npm run build:srs-geoip`
- Update D1 seed SQL: `npm run build:d1`

R2 sync or KV uploads: `npm run r2:sync`, `npm run kv:put:index`, `npm run kv:put:geoip-index`.
